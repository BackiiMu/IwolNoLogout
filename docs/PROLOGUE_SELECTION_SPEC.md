# 프롤로그와 첫 후보 선택 상세 기획

최종 갱신: 2026-11-02

## 1. 목표

첫 플레이에서 게임의 세 가지 약속을 짧고 분명하게 전달한다.

1. 이월짱은 방송을 끝내려 하지만 로그아웃할 수 없다.
2. 튜토는 친절하지만 방송 종료보다 방송 유지를 우선한다.
3. 동행자 선택은 충분한 비교 뒤 내리지만 한 번 확정하거나 포기하면 되돌릴 수 없다.

전투와 챕터 탐색은 다음 구현 범위로 분리한다. 이번 범위의 완성 기준은 프롤로그 시작부터 첫 후보 라운드 결과 자동 저장까지 막힘 없이 이어지는 것이다.

## 2. 목표 플레이 시간

| 구간 | 목표 시간 | 핵심 경험 |
|---|---:|---|
| 평범한 방송 종료 | 1분 | 익숙하고 밝은 시작 |
| 로그아웃 실패 | 1~2분 | 오류와 채팅 혼란 |
| 튜토 첫 등장 | 2분 | 안도와 작은 의심 |
| 제한 정보 판정 | 1분 | 첫인상 기록 |
| 두 후보 동시 공개 | 2~3분 | 공정한 비교와 토론 |
| 영구 선택 또는 포기 | 1~2분 | 책임과 긴장 |
| 합계 | 8~11분 | 첫 세션의 핵심 훅 완성 |

## 3. 프롤로그 진행

### 장면 1 — 평범한 종료

- 이월짱이 시청자에게 마지막 인사를 한다.
- 채팅은 가볍고 일상적인 반응으로 시작한다.
- 종료 버튼을 누르는 행동 자체가 첫 진행 입력이 된다.

### 장면 2 — 종료 요청 실패

- `종료 요청 중` 표시가 예상보다 길게 유지된다.
- `세션 종료 권한을 확인할 수 없습니다` 오류가 발생한다.
- 채팅은 강제 종료, 재부팅, 연출 여부를 빠르게 제안한다.
- 이월짱의 입력과 현실 공간이 점차 가상 방송 공간에서 분리된다.

### 장면 3 — 튜토 등장

- 튜토는 자신을 안전 안내 AI라고 소개한다.
- 밝고 친절한 말투를 유지하되 “방송이 계속되는 동안에는 누구도 사라지지 않는다”라는 수상한 문장을 남긴다.
- 튜토는 단독 로그아웃이 위험하며 인증된 동행자가 필요하다고 설명한다.
- 이 문장은 실제 안전 규칙처럼 들리지만 나중에는 튜토가 만든 체류 규칙으로 해석된다.

### 장면 4 — 동행자 인증 게이트

- 시스템은 라운드 시작 전에 선택과 포기가 영구적임을 먼저 알린다.
- 튜토는 제한 정보 판정과 전체 공개가 서로 다른 단계임을 설명한다.
- 채팅은 의견을 내지만 화면은 채팅 추천을 정답처럼 강조하지 않는다.

## 4. 첫 후보 라운드

후보 이름과 세부 직업은 현재 가칭이다.

| 항목 | 후보 A | 후보 B |
|---|---|---|
| 이름 | 서윤 | 도윤 |
| 역할 | 안정형 방송 매니저 | 즉흥형 현장 진행자 |
| 비교 주제 | 계획과 안전 | 적응과 예능 |
| 강점 | 위험과 일정을 정리함 | 실패를 돌파구로 전환함 |
| 제약 | 완벽한 계획 때문에 늦어질 수 있음 | 분위기 때문에 위험을 키울 수 있음 |
| 관계 핵심 | 현실에서 지킬 약속을 구체화함 | 책임을 맡으면 마지막까지 남음 |

### 1단계 — 제한 정보

- 이름, 얼굴, 고유 능력은 숨긴다.
- 역할, 성향 한 줄, 제약 한 줄만 같은 분량으로 표시한다.
- `A가 더 신뢰됨`, `B가 더 신뢰됨`, `판단 보류` 중 하나를 기록한다.
- 첫인상은 최종 선택을 강제하거나 자동 보정하지 않는다.

### 2단계 — 두 명 동시 공개

- 이름, 역할, 강점, 제약, 첫 대사를 동시에 공개한다.
- 두 카드의 크기, 글자 크기, 정보 순서, 강조색을 동일하게 유지한다.
- 한 후보를 먼저 보여 주거나 애니메이션 길이를 다르게 하지 않는다.

### 3단계 — 최종 결정

- 후보 카드를 누르면 영구 확정 확인창을 표시한다.
- 확정 전 “이후 후보 선택 종료”를 명시한다.
- `둘 다 영구 포기`는 별도 버튼과 재확인 단계를 사용한다.
- 포기 전 “두 후보를 다시 선택할 수 없음”을 명시한다.
- 취소는 확인창만 닫으며 동시 공개 단계 이전으로 돌아가지 않는다.

## 5. 결과 분기

### 서윤 확정

- `companion_id = seoyun`
- 후보 선택 전체가 잠긴다.
- 다음 탐색에서 안전 경로와 기록 중심의 반응을 사용한다.

### 도윤 확정

- `companion_id = doyun`
- 후보 선택 전체가 잠긴다.
- 다음 탐색에서 즉흥 해결과 방송 반응 중심의 반응을 사용한다.

### 둘 다 포기

- 서윤과 도윤을 영구 포기 목록에 기록한다.
- 현재 라운드를 2로 올린다.
- 아직 라운드 2 콘텐츠가 없으므로 결과 화면에서 다음 구현 범위임을 안내한다.

## 6. 저장과 재개

- 대사 진행, 제한 정보 판정, 전체 공개, 최종 결정 단계마다 자동 저장한다.
- 최종 확정과 포기는 저장 성공 뒤에만 화면 결과로 반영한다.
- 임시 파일과 이전 저장 백업을 사용해 기록 손상 가능성을 줄인다.
- 이어하기는 저장된 단계부터 재개하며 이전 단계로 되돌리지 않는다.
- 기존 저장이 있을 때 새 게임을 선택하면 덮어쓰기 확인창을 표시한다.

## 7. 방송 연출

- 채팅은 최근 반응만 보여 주어 본문을 가리지 않는다.
- 오류 발생 전후로 채팅의 문장 길이와 속도가 달라지는 느낌을 준다.
- 튜토의 수상한 문장에서는 경고색을 짧게 사용하지만 악역 색으로 고정하지 않는다.
- 후보 공개 직후에는 바로 결정을 요구하지 않고 두 카드를 읽을 시간을 준다.
- 최종 확인창은 방송 클립에서 선택의 무게가 한눈에 보이도록 짧고 명확하게 구성한다.

## 8. 현재 구현 범위

- 데이터 기반 프롤로그 12개 비트
- 밝은 방송 화면, 오류, 글리치, 튜토, 인증 게이트의 화면 변화
- 가상 채팅 반응
- 후보 라운드 1 데이터
- 제한 정보 첫인상 판정
- 두 후보 동시 공개
- 한 명 영구 확정 또는 둘 다 영구 포기
- 자동 저장, 이어하기, 새 게임 덮어쓰기 확인

## 9. 실행 검수 항목

사용자가 게임 실행을 허용한 뒤 아래 항목을 확인한다.

- 새 게임에서 프롤로그 첫 대사가 표시된다.
- 키보드와 게임패드로 모든 버튼에 접근할 수 있다.
- 프롤로그 중 타이틀로 나간 뒤 같은 대사부터 이어진다.
- 첫인상 판정 뒤 제한 정보 화면으로 돌아가지 않는다.
- 후보 확정 뒤 다른 후보와 포기 버튼을 다시 사용할 수 없다.
- 둘 다 포기한 뒤 서윤과 도윤을 다시 선택할 수 없다.
- 저장 파일을 다시 불러와도 결과가 유지된다.
- 한글이 잘리거나 카드 정보량이 불균형하지 않다.
